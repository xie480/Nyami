# 修复 B 站授权续期失败

## 1. 背景与目标

应用保存 B 站 Cookie 与轮换用的 refresh_token，并在会话需要续期时通过第一方 WebView 调用 B 站网页续期流程。用户反馈续期总是失败。本次目标是定位并修复续期流程中的确定性失败点，同时保持凭证仅在 B 站页面与本地安全存储之间传递。

## 2. 现状与问题

LoginModal 先请求 B 站 correspond 页面，再解析其中的续期 CSRF 值，随后调用 Cookie refresh 与 confirm 接口。脚本捕获错误后只发送统一失败事件，因此具体页面解析错误也会显示成“续期失败”。

## 3. 排查与根因

- **已确认事实：** BILIBILI_REFRESH_CSRF_SELECTOR 配置为 #1-name，续期脚本通过 Document.querySelector 查找该元素。
- **已确认根因：** 1-name 以数字开头，原始 #1-name 不是有效的 CSS ID 选择器。querySelector 会抛出 SyntaxError，被脚本最外层 catch 捕获并转换为 cookie-refresh-error。因此，即使前序网络请求成功，解析此字段时仍会失败。
- **边界：** 该修复消除代码中的确定性解析错误；B 站接口响应、设备 WebView Cookie 状态及真实账号续期仍需在设备和网络环境中确认。

## 4. 修复方案

保留 B 站页面中的原始元素 ID 1-name，将配置从 CSS selector 改为元素 ID，并通过 getElementById 获取节点。这不依赖 CSS 转义规则，也不改变凭证、请求参数或域名边界。

## 5. 核心修改

- LoginModal 将续期参数中的 refresh CSRF 字段读取改为 getElementById。
- bilibiliAuth 配置将 BILIBILI_REFRESH_CSRF_SELECTOR 改名为 BILIBILI_REFRESH_CSRF_ID，值仍为 1-name。
