# 首次全局索引同步提醒记录

## 1. 背景与目标

桌面端首次使用收藏相关功能前需要先建立全局索引。当前应用没有主动提醒，用户登录后容易直接进入空的收藏内容。本次增加一次性的 Windows 通知，提醒用户先完成全局索引同步。

## 2. 触发条件与一次性规则

- 仅在账号已经登录且本地尚未建立成功的收藏索引时发送提醒。
- 应用启动时检查一次；二维码或网页登录成功后再次检查，覆盖启动时尚未登录的场景。
- 提醒状态写入 settings 目录下的独立标记文件，展示或确认不需要提醒后都不再重复发送。
- 已经存在本地索引的老用户不会收到无效提醒，并会直接写入完成标记。

## 3. 核心修改

- `SettingsStore` 新增一次性提醒标记的读取和原子写入方法，不改变已有 `DesktopSettings` 公共契约。
- `DesktopShell` 使用现有 Windows 通知入口发送“首次使用提醒”，并复用通知点击后的主窗口恢复逻辑。
- `createWindow` 在账号切换或登录完成后触发检查，确保登录发生在窗口启动之后也能收到提醒。

## 4. 风险与影响范围

- 标记文件属于当前用户数据目录，卸载时是否清理由安装配置决定；重新安装并保留用户数据时不会重复提醒。
- Windows 通知服务不可用时只记录日志，标记仍会写入，避免每次启动重复打扰。
- 本次不自动启动同步任务，用户仍需从同步入口主动执行全局索引同步。

## 5. 验证方案与结果

- `npm run desktop:typecheck` 已通过。
- `npm run desktop:build` 与 `git diff --check` 在提交前执行并记录结果。
- 未在真实 Windows 通知中心手动验证首次登录、通知去重和点击行为，需要在目标环境补做实机验收。

## 6. 最终结论

桌面端现在会在首次登录且没有本地全局索引时提醒用户先同步；提醒状态持久化后只展示一次，不会在后续启动重复出现。
