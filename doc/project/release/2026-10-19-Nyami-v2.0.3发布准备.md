# Nyami v2.0.3 发布准备

## 1. 背景与目标

用户要求将当前本地改动整理为新版本，更新版本号，在 `release/` 编写发布日志，并生成 Android Release APK。

初始工作区干净，没有未提交文件。当前分支为 `yilena/global-ui-polish`，相对本地远端跟踪引用 `origin/main`（`8b84395`，v2.0.2 发布提交）增加了 5 个本地提交，因此本次以这 5 个提交作为发布范围。未联网刷新远端状态；这里的“未推送”依据本地远端跟踪引用判断。

## 3. 方案与核心修改

- 沿用现有 Android 发布版本序列，由 `2.0.2 / versionCode 3` 升为 `2.0.3 / versionCode 4`；递增 versionCode 以支持安装升级。
- 同步 `android/app/build.gradle`、设置页版本显示和 README 当前版本及更新日志入口。
- 新增 `release/RELEASE_NOTES_v2.0.3.md`，按用户可感知的功能与修复整理 5 个提交。
- 沿用项目现有 release 签名、压缩及 ABI 拆分配置，输出 `arm64-v8a`、`armeabi-v7a` 两个 APK。
- 沿用此前发布范围，JavaScript 私有包版本和 iOS 版本不随本次 Android 发布修改。
- 签名凭据不输出、不复制到日志或文档。

## 5. 风险与验证边界

- 历史记录中全量 Jest 有 3 套原生依赖 Mock 初始化失败，完整 TypeScript 有既有诊断；本次需如实记录实际执行的检查，不把定向通过等同全量通过。
- 本次构建保留 AGP 8.2.1 对 `compileSdk 35` 的兼容范围提示、Gradle 9 弃用提示以及 Hermes 的全局变量警告，未因此失败；没有为消除提示修改依赖或编译配置。
- 签名和包元数据校验不能证明真机安装、界面布局、TalkBack、账号登录、真实音频输出或覆盖安装成功；本次暂未验证这些设备与账号行为。
- 不修改分支历史，不推送、不发布远端 Release。

Android v2.0.3 Release 已生成，7 套、61 项相关回归全部通过；两个 ABI 安装包完成签名、版本、架构、不可调试状态和哈希检查。README 与设置页显示一致，发布日志位于 `release/RELEASE_NOTES_v2.0.3.md`。
