# 测试文件集中管理

## 1. 背景与目标

项目中的自动化测试、手动 API 诊断脚本和 iOS XCTest 文件分散在仓库根目录、`__tests__/` 与 `ios/BiliMusicTests/`。本次将测试相关文件集中到仓库根目录的 `tests/`，并保留不同运行方式的边界。

## 2. 现状与需求

- React Native/Jest 自动化用例原先位于根目录 `__tests__/`。
- 16 个以 `test_` 命名的 JavaScript/Python API 诊断脚本和一个 `check_tp.js` 依赖检查工具原先散落在仓库根目录。
- iOS XCTest 源码和 `Info.plist` 原先位于 `ios/BiliMusicTests/`，Xcode 工程通过 `project.pbxproj` 引用。
- Jest 配置原先使用默认测试匹配规则，没有把自动化用例位置限定到统一目录。

## 3. 方案与目录结构

按执行方式分类，统一放入 `tests/`：

```text
tests/
├── unit/     # Jest 自动化用例
├── manual/   # 手动 API 与依赖诊断工具
└── ios/      # XCTest 源码与 Info.plist
```

这种分组能保留 Jest 与 iOS 原生测试的既有入口，同时让手动诊断工具不会被默认 Jest 命令误选。

## 4. 核心修改

- 将 10 个 Jest 用例移动到 `tests/unit/`，并把指向项目源码的相对导入更新为新的层级。
- 将 16 个 `test_*` API 诊断脚本和 `check_tp.js` 移动到 `tests/manual/`，并调整后者对仓库根目录 `node_modules` 的定位。
- 将 iOS XCTest 源码与 `Info.plist` 移动到 `tests/ios/`；更新 Xcode 工程组路径与 Debug/Release 的 `INFOPLIST_FILE`。
- 在 `jest.config.js` 中将 `testMatch` 限定为 `tests/unit/` 下的 `.test` 文件，同时保留默认仓库根搜索范围，让 `App.tsx` 与 `src/` 源文件仍处于 Jest 文件索引范围。
- 在 README 中记录新目录结构与 `npm test` 的测试入口。

## 5. 影响范围与风险

本次只移动测试与诊断文件，并同步更新 Jest、Xcode 工程路径；应用运行时代码和依赖未改动。主要风险是路径配置遗漏，影响 Jest 测试发现或 Xcode 测试目标构建。

## 6. 验证方式与结果

- 已核对目录清单：`tests/unit/` 有 10 个文件，`tests/manual/` 有 17 个文件，`tests/ios/` 有 XCTest 源码和 `Info.plist`。
- 已搜索 Jest 用例中的项目源码导入，路径均已调整到 `../../src/` 或 `../../App`。
- `node --check jest.config.js` 通过。
- 未运行 Jest 用例或 Xcode 构建；因此测试运行时发现与 iOS target 构建仍待在相应环境中确认。

## 7. 后续事项

在可运行项目测试的环境中执行 `npm test`；如维护 iOS target，再执行对应 Xcode 测试构建。
