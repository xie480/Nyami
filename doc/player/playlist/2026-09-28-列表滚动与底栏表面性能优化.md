# 列表滚动与底栏表面性能优化

## 1. 背景与目标

用户反馈推荐列表下滑更新慢、推荐合集续页不及时，以及不同界面上下滚动普遍卡顿；同时要求导航栏、播放条和首页卡片去掉黑色投影及明显的多层嵌套高光。

本次从列表卡片的视图层数、模糊加载和分页触发距离入手，保留现有 B 站 API 自适应限速。

## 2. 现状与证据

- `GlassView` 常规模式除背景外还创建边缘色散、内高光、右下高光、颗粒层和可选底边阴影等绝对定位视图；模糊层在交互空闲后另外挂载。
- Android 下玻璃容器默认 `collapsable=false`，会保留额外原生容器节点。
- 发现页首页卡片和播放列表推荐卡片位于可滚动内容；播放列表推荐卡片此前仍创建 `BlurView`，其它部分卡片即使关闭 blur 也保留多层绝对定位装饰。
- 歌曲推荐和合集列表原先分别在距底部 0.6 与 0.5 个视口时触发下一页；网络请求仍受全局共享令牌桶约束。

## 3. 方案与核心修改

- `GlassView` 增加 `minimal` 轻量模式：使用单层底色/细边框，不创建模糊、边缘高光、颗粒或环境阴影，并允许 Android 折叠不需要的包装节点。
- 发现首页卡片、合集推荐列表卡片、底部导航、迷你播放条和播放列表面板使用轻量模式。底部播放条同时显式关闭独立阴影；外框只保留一层细边框，导航选中态继续由单个移动指示器表达。
- 歌曲推荐和合集推荐列表把触底阈值提前到 1.2 个视口，让下一页请求更早开始；保留加载互斥、账号校验、取消控制和 API 自适应限速。

## 4. 风险与影响范围

- 轻量模式减少列表表面层数和原生 blur 节点，但无法单凭静态代码确认所有设备上的滚动帧率提升；自定义背景图片本身的解码/模糊仍可能成为部分设备的瓶颈。
- 提前请求会增加用户未滚到列表底部时已开始的续页请求；单页结果仍遵守既有去重和 UID 校验。
- 本任务保留用户此前指定的主页面无左右滑动、页面切换无过渡动画行为。

## 5. 验证方式与结果

- 静态检查确认轻量模式跳过模糊与装饰节点，推荐列表阈值已提前；未修改全局请求限速值。
- `git diff --check` 通过。
- 未运行测试、构建、lint 或真机性能采样；实际帧率仍待设备验证。
