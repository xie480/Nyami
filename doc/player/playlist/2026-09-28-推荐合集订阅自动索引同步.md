# 推荐合集订阅与自动索引同步

## 1. 背景与目标

让用户能从首页合集推荐中将感兴趣的 B 站外部收藏夹/合集加入本机收藏夹，并自动同步其中的视频、全局索引与视频标签。

## 2. 已确认的现有链路

- 推荐合集由 `importedPlaylistService.getCollectedPlaylists(uid)` 提供；当前接口只枚举本 B 站账号已经收藏/订阅的外部来源。
- `useImportedPlaylistStore` 已按 UID 持久化完整来源目录和 `visibleSourceKeysByUid`；`FoldersScreen` 根据可见来源键将外部列表显示在收藏夹界面。
- `useSyncStore.startSync` 会读取当前 UID 的可见外部来源并调用 `favoriteService.syncGlobalIndex`；每批新视频通过 `addFavoriteVideosToTagBackfill` 加入既有标签队列。
- 因此本需求的“订阅”按本机接入/显示该来源实现，复用当前 B 站收藏关系，不新增 B 站远端收藏写操作或数据库表。

## 3. 实施内容

1. 首页预览卡与合集推荐完整列表均在合集名称/UP 主信息附近内联显示订阅按钮，避免按钮掉到卡片底部；展开/播放合集仍由卡片内容点击触发，订阅按钮使用独立触摸区域。
2. 订阅时按当前 UID 幂等补全来源目录和 `visibleSourceKeysByUid`，然后调用既有 `startSync`，复用 B 站来源拉取、WatermelonDB 增量索引与标签回填。
3. 全局同步已运行时，在同步 Store 合并同 UID 的待执行请求，并在当前任务结束后顺序补跑一次，避免旧同步快照漏掉刚加入的来源；取消同步会清除待执行请求。
4. 按钮显示处理中/已订阅状态；同步失败会反馈错误，但保留本机订阅以便用户后续重试。
5. 从推荐入口进入合集视频列表后，在顶部封面工具栏继续显示同一订阅按钮，复用相同 UID 隔离、同步队列与状态反馈。

## 4. 风险与验证

- 同步队列合并同 UID 的短时间重复请求，避免并行重复写入；已有 `favoriteService` 同步互斥锁和 playlist 元数据增量检查继续作为底层保护。
- 新来源通过用户当前账号 Cookie 读取；失败时不可伪装为成功同步。
- 本机订阅和目录可见状态经 MMKV 持久化；若用户确指 B 站远端订阅未订阅来源，则当前推荐源目录不足以发现这些来源，需另行接入 B 站搜索/发现接口。
- 代码核对与 `git diff --check` 确认按钮写入 UID 隔离的可见来源、同步队列后续重跑及标签回填复用路径；未运行构建、测试或真实 B 站账号流程，运行结果仍待设备验证。
