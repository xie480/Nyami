# 修复收藏夹主页无限更新错误

## 1. 背景与目标

应用启动或打开首页收藏夹时，React Native 输出 `Maximum update depth exceeded`，调用栈指向 `FoldersScreen`。目标是定位造成持续状态更新的代码并以最小改动恢复首页渲染。

## 2. 现状与排查证据

- `src/screens/FoldersScreen.tsx` 订阅外部收藏目录和首页可见来源列表；两项数据按 B 站 UID 存放在 `useImportedPlaylistStore` 中。
- `src/store/importedPlaylistStore.ts` 的初始 `catalogByUid` 和 `visibleSourceKeysByUid` 均为空对象，尚无对应用户缓存时，组件需要返回空列表。
- 近期提交 `098e451` 为外部收藏主页新增了这两个 selector，缺省分支内联返回 `[]`。
- 项目使用 Zustand `5.0.12`。其 React hook 通过 `useSyncExternalStore` 读取 selector 结果；selector 若每次读取缺省数据都新建数组，快照引用会持续变化。
- 用户提供的堆栈明确指向 `FoldersScreen`；未在本机设备上复现，修复依据是堆栈与 selector/store 实现相互印证。

## 3. 根因

缺省分支每次返回新的数组引用，破坏了外部 store 快照的引用稳定性。React 因而将同一份空数据反复识别为变化，持续安排渲染，最终触发最大更新深度警告。

## 4. 修复方案

在模块作用域定义稳定的空目录和空来源键数组，并让两个 selector 在 UID 缺失或用户数据未初始化时复用这些引用。已有数据仍直接返回 store 中的数组；不修改持久化格式、加载流程或业务行为。

## 5. 核心修改与影响范围

- `src/screens/FoldersScreen.tsx`：为两个缺省数组改用稳定常量。
- 影响范围限于首页外部收藏数据为空时的 Zustand 订阅快照；已存在的收藏数据和过滤逻辑不变。

## 6. 验证方案与结果

- `git diff --check` 通过。
- 本次新增的稳定数组与 selector 片段没有 ESLint 诊断；对整个 `FoldersScreen.tsx` 执行 ESLint 仍会报告大量文件级 Prettier/CRLF 格式问题，未对该历史文件做全量格式化。
- 登录修复涉及的 `LoginModal.tsx`、`bilibiliAuth.ts`、`biliLoginService.ts` 定向 ESLint 通过。
- 真机启动及首页加载尚未验证；本次不把静态检查描述为设备运行验证。

## 7. 后续事项

如果设备上仍出现同一警告，应继续检查 `FoldersScreen` 的其它 store selector 是否返回每次新建的对象或数组，并记录触发时的登录 UID 与外部收藏初始化状态。

## 8. 偏好页面回归排查与修复

### 现象与证据

- 用户打开“主页播放列表偏好”时收到 `Maximum update depth exceeded`，堆栈指向 `VisibleFoldersScreen`；页面也没有显示“我追的合集/收藏夹”。
- `src/screens/VisibleFoldersScreen.tsx` 的 `importedSources` 和 `visibleSourceKeys` 在对应 UID 尚无缓存时都返回内联 `[]`。项目使用 Zustand 5.0.12，其 hook 用 `useSyncExternalStore` 返回 selector 快照。
- 同屏 `useEffect` 以 `visibleSourceKeys` 为依赖，并在每次执行中 `setLocalVisibleSources(new Set(visibleSourceKeys))`。新建 Set 会更新本地状态；内联空数组又会让依赖引用每次渲染都改变，构成稳定的更新循环。
- 外部来源由 `load()` 调用 `importedPlaylistService.getCollectedPlaylists(uid)`；服务请求 `/x/v3/fav/folder/collected/list`，公共 HTTP 拦截器会注入已保存 Cookie，再把返回项归一化后写入按 UID 隔离的 store。此调用链说明页面有读取与展示这些来源的路径；本次没有真机验证用户账号的实际接口响应。
- 同步错误原先只在列表非空分支中渲染。当外部来源同步失败且没有自有收藏夹时，页面落入空状态，用户看不到失败原因或重试入口。

### 修复

- 在 `VisibleFoldersScreen` 中复用稳定的空目录和空来源键数组，避免无缓存状态生成不稳定的 Zustand 快照，并让同步本地可见状态的 effect 只在数据引用实际变化时运行。
- 将偏好数据按“我创建的收藏夹”和“我追的合集/收藏夹”分组展示，匹配用户提供的界面分类。
- 外部同步失败且没有可展示条目时显示错误和重试入口；同步失败但仍有历史条目时继续保留旧目录并显示提示。

### 验证

- `git diff --check` 通过。
- 全量 TypeScript 检查未通过，但报告仅涉及 `folderDataStore.ts` 的既有 null 类型问题及根目录 `trackPlayer_backup.ts` 的旧文件导入/隐式 any 错误；未报告 `VisibleFoldersScreen.tsx` 错误。
- `VisibleFoldersScreen.tsx` 全文件 ESLint 仍有大量既有 Prettier/CRLF 诊断；新增 selector、分组数组和同步错误分支没有对应诊断。未对整个历史文件运行自动格式化。
- 尚未在真机验证 B 站返回的已追收藏夹和合集目录；实际返回数据仍取决于当前登录 Cookie 与接口响应。
