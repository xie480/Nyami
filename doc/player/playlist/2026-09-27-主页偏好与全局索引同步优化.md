# 主页偏好、全局索引、底部播放导航与标签后台提取优化

## 1. 背景与目标

本次工作沿用主页偏好和全局索引优化，补充处理五项用户反馈：全局随机播放显示当前可见曲库歌曲数；自有收藏夹全部隐藏时仍可同步主页偏好中选中的“我追的合集/收藏夹”；底部播放条与悬浮磨砂导航合并为同一块玻璃面板并在应用级持续显示；全局索引同步完成后自动在后台提取兴趣标签。

## 2. 现状与排查证据

- `src/services/favoriteService.ts` 原有 `syncGlobalIndex` 只通过 `getFolders()` 构造同步任务，任务 ID 均为自有收藏夹数字 ID。外部来源虽被 `FoldersScreen` 展示并保存在 `importedPlaylistStore`，但没有进入全局同步任务，因此当自有收藏夹都被隐藏时会抛出“自有收藏夹当前均已在主页偏好中隐藏”的错误。
- `ImportedPlaylist.sourceKey` 由来源类型、所有者 UID 和远端列表 ID 组成，且主页显示选择按当前 B 站 UID 保存；可用它识别已选外部来源。
- `playlist_meta.playlist_id` 和 `video_meta.playlist_id` 在现有 WatermelonDB 模型中是字符串，数据库操作按字符串参数查询和写入；外部 `sourceKey` 可复用该字段，不需要 schema 迁移。
- `loadGlobalIndexCache` 以前仅把 `playlist_id` 转为数字 `folderIds`。直接读取外部来源索引会得到无效的数字身份，无法按外部来源选择过滤；同一 BVID 的多来源归属也需合并。
- `FoldersScreen` 搜索栏右侧的齿轮和标签图标分别进入设置与收藏标签推荐；当前已有 `GlassView` 可用于实现磨砂导航，无需增加 UI 依赖。
- 上一轮已移除每个同步页请求前额外随机等待的 1–3 秒；B 站请求仍由现有 `adaptiveBucket` 限流（配置上限每秒 1 次），同步跳过已是最新的列表。
- 兴趣画像原先只在用户打开画像页并点击按钮后提取标签；页面离开时会中断这项手动任务。每个视频标签单独请求并写入缓存，标签读取与索引同步共用 B 站全局限速。
- 原底部播放器和导航各自绘制背景时形成上下相邻的独立视觉块；用户选择将播放信息与导航放进同一个底部磨砂面板。
- 最近一次改造虽然把播放条和导航合并成一个面板，但面板仍分别挂载在 `FoldersScreen`、`SettingsScreen` 和 `TagRecommendationsScreen`；`VideosScreen` 还保留一个独立播放器。进入其他路由时组件会卸载或换成另一个实例，因此播放条不能跨导航变化稳定保留。

## 3. 根因与判断

### 已确认

1. “仅自有收藏夹可同步”是此次外部来源报错的直接代码原因：外部选择没有被 `syncGlobalIndex` 读取或转成同步目标。
2. 外部来源 ID 是稳定字符串；数据库存储和查询已支持，不必迁移表结构。
3. 全局曲库按 BVID 去重后，需要同时保留所属自有收藏夹 ID 和外部来源 key，否则重复歌曲可能因某一个来源隐藏而被错误过滤。
4. 同步速度优化不能通过提高 B 站请求速率实现；本次沿用现有限流和增量跳过策略，不虚构提速比例。
5. 标签读取可与索引任务并行或异步收尾。由于两者共享限速器，并行会延长主索引同步，本次选择索引结束后异步启动；下次索引同步开始时主动暂停标签任务。
6. 标签提取进度放在进程内状态中，标签缓存与重试冷却时间继续持久化在 WatermelonDB；应用进程被系统结束时，未完成队列本身不会持久化，后续索引同步可根据缓存续读。
7. 全局播放器面板放在应用壳层的 `NavigationContainer` 同级，并通过根导航 ref 驱动目的地；屏幕之间切换时保持同一组件实例。启动页、未登录欢迎页和全屏播放器页不显示底部面板，避免覆盖启动/登录内容或完整播放器。

### 尚未验证

未在真实账号和设备复现原报错，也没有同步耗时基线或新旧耗时对照。当前结论基于实际调用链和数据模型代码。

## 4. 方案设计与取舍

- 同步目标由“主页偏好中未隐藏的自有收藏夹”与“当前 UID 选中的外部收藏夹/合集”组成。外部目录在手动同步时刷新，避免目录变化后沿用旧视频数；按选中 `sourceKey` 精确挑选有效来源。
- 外部来源用完整 `sourceKey` 作为 `playlist_id`；自有收藏夹仍使用原数字 ID 字符串。复用分页、增量判断、WatermelonDB 批量写入、任务进度和失败汇总逻辑。
- 全局索引映射时区分数字自有 ID 与字符串外部 key，并在同一 BVID 去重条目上合并两类来源。歌曲只要存在一个未隐藏或已选来源即可显示、计数和参与全局随机播放。
- 底部导航采用现有 `GlassView` 与安全区 inset。导航包括后续开放的“首页”占位、当前“收藏夹”、现有标签画像页（显示为“用户画像”）和“设置”。“首夜”按“首页”处理。
- 主页保留搜索栏内部的搜索/模式操作，移除搜索栏右侧独立的设置和标签推荐图标。
- 同步仍依赖已有 B 站限流；通过移除多余等待和跳过本地已是最新的数据减少无效耗时，不并发突破接口节流。
- 兴趣标签回填作为全局索引的异步收尾工作执行；顺序调用原有 `backfillFavoriteTags`，复用 30 天标签缓存、新失败冷却和单视频即时写库。新一轮索引同步开始时中止后台请求，已完成缓存保留，待索引完成后再按最新全局可见集合调度。
- 新增按 UID 隔离的进程内回填状态，画像页展示后台进度、暂停或错误；后台任务结束且画像页仍打开时重新载入本地快照。下次索引同步会重新枚举视频，已缓存或处于重试冷却期的视频由既有逻辑跳过。
- 播放条嵌入 `BottomNavigationBar` 的统一 `GlassView`，由导航面板绘制唯一的磨砂背景和外边框；删除收藏夹页原先独立的底部 `MiniPlayer`。
- `App.tsx` 根据根导航的 `onReady` / `onStateChange` 读取当前 route，在 `NavigationContainer` 外侧、应用根布局中统一挂载唯一的 `BottomNavigationBar`。主导航页与视频、同步详情等普通路由共享同一个底部面板，活动导航项随 route 映射更新。
- 从 `FoldersScreen`、`SettingsScreen`、`TagRecommendationsScreen` 移除页面内导航，从 `VideosScreen` 移除独立播放器，避免页面切换时卸载或重复渲染。`MiniPlayer` 改为通过 `onOpenPlayer` 回调打开全屏播放器，因此全局 dock 不依赖某个 Screen 的 `useNavigation` 上下文。

## 5. 核心修改

- `src/types/domain.ts`：为 `FavoriteVideo` 增加可选 `sourceKeys`，表示外部收藏夹或合集来源。
- `src/services/favoriteService.ts`：读取数据库视频时将数字 `playlist_id` 映射为 `folderIds`，非数字 ID 映射为 `sourceKeys`；重复 BVID 合并来源身份。全局可见索引支持同时按隐藏自有 ID 和当前选中的外部 key 过滤。
- `src/services/favoriteService.ts`：同步开始时读取当前 UID 的外部来源选择并刷新目录；将可见自有收藏夹与所选外部列表构造成统一任务，外部视频经 `importedPlaylistService` 拉取，使用 `sourceKey` 写入现有索引表。目录中找不到所选来源时显示明确错误；单列表失败仍汇总到同步状态。
- `src/screens/FoldersScreen.tsx`：随机入口显示“全局随机播放”和当前去重歌曲数；随机候选与搜索索引按当前主页偏好筛选。移除搜索栏右侧两个图标。
- `src/screens/SettingsScreen.tsx`：全局索引歌曲数使用同一套自有/外部可见来源过滤，并添加设置页底部导航。
- `src/components/BottomNavigationBar.tsx`：新增安全区适配的悬浮圆角磨砂栏，使用现有 `GlassView`；提供“首页（后续开放）”“收藏夹”“用户画像”“设置”。
- `src/components/BottomNavigationBar.tsx`、`src/components/MiniPlayer.tsx`：选择单面板方案，活动播放器行、进度线和导航入口共享一个玻璃背景；播放器行不再单独绘制圆角玻璃。
- `src/store/syncStore.ts`、`src/services/tagRecommendationService.ts`、`src/store/tagBackfillStore.ts`：在索引成功或部分完成后异步安排标签回填；下一轮索引开始时中断标签请求，UID 校验避免跨账号写入进度。
- `src/screens/TagRecommendationsScreen.tsx`：展示后台标签提取进度、暂停和错误状态，任务完成后刷新画像；后台读取期间禁用重复提取按钮。
- `src/screens/TagRecommendationsScreen.tsx`：画像统计按当前主页可见来源计算，并添加对应选中态的底部导航；`src/screens/FoldersScreen.tsx` 同样接入收藏夹选中态。
- 上一轮保留的修改：主页偏好条目改为来源标签、标题、UP 主/视频数、选中状态清晰的单层卡片；同步错误可见、完成状态不闪退；同步循环删除额外随机等待。

## 6. 风险与影响范围

- 外部来源目录刷新和视频分页依赖当前账号的 B 站接口响应；无网络或来源已从账号目录移除时会失败并反馈，不应被显示成成功。
- 外部索引在本机按 `sourceKey` 隔离；登录账号切换仍由应用既有数据库清理流程负责。UID 作用域的来源选择与目录存储逻辑保持不变。
- 数据表没有变化，旧数据库无需迁移。同步详情页目前仍按自有收藏夹展示，因此不会将外部来源伪装成自有收藏夹。
- 同步速度仍受现有每秒一次请求限流、来源数量、分页数量和网络影响；尚无测量数据证明具体提升幅度。
- 底部导航和搜索栏的设备视觉、触控范围与小屏遮挡尚未在真实设备验证。
- 全局 dock 持续占据根布局底部高度，导航栈可用高度相应减少；页面主内容以 flex/滚动布局为主，但各小屏、键盘弹出和次级路由的最终空间仍需在目标设备复核。
- 兴趣标签接口仍按原限速逐个请求，大型曲库可能需要较长时间才能全部完成；此任务不启用独立的 Android 后台执行服务，应用被系统结束后未完成队列会等到下次索引同步重新扫描。已成功读取的标签会保留，网络、认证、限流失败仍遵循原冷却和重试策略。

## 7. 验证方式与结果

- 已检查服务调用路径：主页选择状态 → 当前 UID 外部目录 → `syncGlobalIndex` 同步目标 → 外部分页服务 → 字符串 `playlist_id` 持久化 → 来源身份合并和可见索引筛选。
- 已检查页面调用：主页随机播放和设置页索引数量使用同一可见来源集合；导航接入收藏夹、画像和设置页面，未来首页明确为禁用占位。
- 已检查数据库 schema 与操作签名，确认 `playlist_id` 为字符串且批量写入/计数/软删除均接受字符串 ID，无表结构变更。
- `git diff --check` 通过；仅有 Git 对工作区 LF/CRLF 的规范化提示，没有空白错误。
- 已检查后台任务入口：当前全局索引同步由 `SettingsScreen` 统一经 `syncStore.startSync` 发起；正常完成及已有播放列表成功的部分失败会安排标签读取，预检失败或用户取消不会启动后台任务。
- 已检查 `MiniPlayer` 与 `BottomNavigationBar` 引用：播放器和导航目前只在 `App.tsx` 的根布局统一挂载，常规路由按当前 route 更新选中项；全屏播放器和启动/欢迎页隐藏 dock。
- 已静态检查标签任务按 UID 校验、顺序复用原限速 API、每项即时写入缓存，以及索引启动时中止后台任务的控制流。
- `eslint --quiet --rule 'prettier/prettier: off'` 对播放器/导航组件及收藏夹、画像页面通过。扩展到 `App.tsx`、`SettingsScreen.tsx`、`VideosScreen.tsx` 后报告 18 个既有错误（未使用导入/状态及旧 Hook 依赖）；这些错误位于原有代码，本次根布局与组件接线没有新增 lint 错误。仓库默认 Prettier 规则还会把现有 CRLF 文件按 LF 逐行报格式差异，本次没有对整文件做换行重写。
- `tsc --noEmit` 未通过，但错误集中在未修改的 `src/store/folderDataStore.ts:136`（可空数字参数）和根目录 `trackPlayer_backup.ts`（失效导入及隐式 any）；本次修改文件没有出现在类型错误列表中。
- 未运行自动化测试或完整构建，未进行真实设备/账号验证；提速幅度和 B 站外部收藏接口运行结果待实机确认。

## 8. 最终结果与后续事项

代码现已将选中的“我追的合集/收藏夹”纳入全局索引同步。自有收藏夹全部隐藏时，只要存在有效选中的外部来源，就会继续同步该来源。主页随机播放显示当前可见去重歌曲数量；唯一的底部播放器与导航面板由应用根布局持有，切换普通路由时持续保留；每轮索引同步结束后自动后台提取当前可见歌曲的兴趣标签，进度和错误在画像页可见，缓存可跨任务续用。

后续建议在真实账号进行一次外部收藏夹与合集同步，确认接口分页/权限、设置页进度、标签回填结果和同步后歌曲数；在目标设备检查统一底栏布局和小屏滚动空间。索引速度与后台标签完成时长仍应通过真实同步耗时前后对照量化。
