# 用户画像缓存与加载统计视觉优化

## 1. 背景与目标

用户反馈多次进入用户画像仍看到加载过程，并指出加载动画、索引统计和标签进度显示较传统。目标是在全局索引版本未变化时直接呈现本机已有画像快照，同时让进度与统计更易读。

## 2. 现状与根因

- 用户画像数据缓存已按 UID、全局索引 revision、隐藏收藏夹和可见外部来源组成的快照键保存；焦点恢复会检查该键并复用画像。
- 但组件卸载后 `initialLoading` 又以 `true` 初始化，快照只在 effect 执行后才被读入，导致缓存命中也会短暂显示整页加载动画。
- 通用 Loading 使用单个系统 `ActivityIndicator`；同步索引和 tag 回填进度主要由细进度条及串联文字构成。

## 3. 方案与核心修改

- 用户画像首屏通过当前 UID 与全局索引 revision 查询模块级画像缓存；缓存命中时同步恢复画像、可见收藏列表和快照键，初始状态不进入全屏 loading。
- 画像快照键仍包含索引版本和来源可见性；全局索引/画像来源改变时沿用现有刷新流程，避免展示过期数据。
- 通用 Loading 使用原生驱动的圆环旋转与图标呼吸，卸载时停止动画；用户画像初次读取复用该组件。
- 标签回填与全局索引统计增加百分比、渐变进度条和分项计数，数字仍使用既有状态字段，不改变业务统计口径。

## 4. 风险与影响范围

- 缓存只在当前进程内保留，应用重启后仍需按现有流程读取本地索引与 tag 缓存；本改动不会跳过账号、索引版本和来源可见性检查。
- 尚未在真机检查不同主题、字体缩放和低端设备上的动画观感。

## 5. 验证方式与结果

- 静态检查确认画像缓存读取键与原快照键一致，UID/索引 revision 改变仍会触发重新读取。
- 未运行测试、构建、lint 或真实设备验证。

## 6. 画像图形化展示

- 将原来按标签名称罗列的 chip 和频次条切换为两个视图：Top 6 收藏标签频次雷达图，以及“收藏视频 → 标签解析 → 兴趣维度”的纵向流程图。画像流程聚焦偏好形成，不展示下游歌曲推荐。
- 雷达图的数值仍直接使用本地 `TagPreference.videoCount`，并按当前最高频标签归一化；标签名称作为维度标注，不新增画像数据或网络请求。
- 流程图计数复用 `TagProfile` 字段，呈现收藏数、含标签视频数和画像维度数；推荐结果仍由页面其他区域展示。
- 使用项目已有 `react-native-svg`，不新增依赖。图表在低于 3 个兴趣标签时仍按现有维度数量绘制；空画像仍展示原有引导文案。
- 未运行构建或设备视觉检查，标签过长时雷达图会截断显示名称，完整标签数据仍保留在画像对象中。

## 7. 通用加载动效升级

- Loading 使用音频能量球构图：中心七段波形采用不同峰值、短周期错峰伸缩，外围两条轨道反向旋转，双光点绕行，扩散光环与核心呼吸共同形成连续运动层次。
- 波形的收缩、驻留与伸展统一由带原生驱动的 timing 序列构成循环；轨道旋转、光环/核心缩放与透明度、状态点同样使用 React Native 原生 Animated driver。组件卸载时停止循环动画。
- 复用现有渐变与主题颜色，无新增依赖；画布固定 160px，保留 `text` 调用接口，不使用投影阴影堆叠层次。
- 本次重排是代码层动效增强；未运行构建或真机性能/视觉对比，最终观感、主题对比度及低端设备流畅度仍待设备验证。

## 8. 用户画像快照跨重启复用（2026-09-29）

### 根因与目标

- 原画像快照保存在模块级 `Map`，仅在 JS 进程内有效；应用重启会丢失它，导致再次进入页面重新读取并汇总 WatermelonDB 标签缓存。
- 原全局索引 revision 是进程内递增值，不能作为 MMKV 跨重启校验键。需要稳定判断索引成员关系和画像所用 tag 缓存是否变化。

### 方案与修改

- 按 B 站 UID 与隐藏收藏夹/可见外部来源范围，将画像快照持久化到 MMKV；进入页面时先同步恢复快照，随后校验本地数据版本。
- 收藏索引增加基于视频 BVID 与来源成员关系的稳定指纹。标签缓存新增持久化修订号，仅当 tag 内容或“尚未解析/已解析”状态变化时推进；清空标签缓存也会推进版本。
- 指纹和 tag 修订号都匹配时，只读取当前可见收藏列表并复用画像，不再重新查询 tag 表或汇总画像；版本变化时重新计算并覆盖快照。
- 账号和可见范围仍纳入快照身份；读取与落盘前继续校验当前 UID，避免跨账号画像复用。标签写入版本在数据库批次前后推进：失败或并发读取最多导致安全的额外重算，不会继续命中旧画像。

### 验证与限制

- 静态检查确认画像读取路径校验 UID、可见范围、索引指纹与 tag 修订号，缓存不匹配时回到本地重算路径；`git diff --check` 通过。关闭 Prettier 规则后的定向 ESLint 与修改前基线均为 6 个 `writer` 未使用错误，数量相同；全仓 TypeScript 检查只报告未修改的 `trackPlayer_backup.ts` 路径/隐式类型错误，修改文件无诊断。
- 未运行测试、构建或设备验证。
- 首次安装没有持久化快照、账号/来源范围变化、收藏成员关系变化、tag 缓存更新或缓存清理后，仍会执行一次本地画像构建；MMKV 快照损坏时也会安全回退重算。
