# 用户画像缓存与加载统计视觉优化

## 1. 背景与目标

用户反馈多次进入用户画像仍看到加载过程，并指出加载动画、索引统计和标签进度显示较传统。目标是在全局索引版本未变化时直接呈现本机已有画像快照，同时让进度与统计更易读。

## 2. 现状与根因

- 用户画像数据缓存已按 UID、全局索引 revision、隐藏收藏夹和可见外部来源组成的快照键保存；焦点恢复会检查该键并复用画像。
- 但组件卸载后 `initialLoading` 又以 `true` 初始化，快照只在 effect 执行后才被读入，导致缓存命中也会短暂显示整页加载动画。
- 通用 Loading 使用单个系统 `ActivityIndicator`；同步索引和 tag 回填进度主要由细进度条及串联文字构成。

## 3. 方案与核心修改

- 用户画像首屏通过当前 UID 与全局索引 revision 查询模块级画像缓存；缓存命中时同步恢复画像、可见收藏列表和快照键，初始状态不进入全屏 loading。
- 画像快照键仍包含索引版本和来源可见性；全局索引/画像来源改变时沿用现有刷新流程，避免展示过期数据。
- 通用 Loading 改为原生驱动的轻量圆环旋转与图标呼吸，卸载时停止动画；用户画像初次读取复用该组件。
- 标签回填与全局索引统计增加百分比、渐变进度条和分项计数，数字仍使用既有状态字段，不改变业务统计口径。

## 4. 风险与影响范围

- 缓存只在当前进程内保留，应用重启后仍需按现有流程读取本地索引与 tag 缓存；本改动不会跳过账号、索引版本和来源可见性检查。
- 尚未在真机检查不同主题、字体缩放和低端设备上的动画观感。

## 5. 验证方式与结果

- 静态检查确认画像缓存读取键与原快照键一致，UID/索引 revision 改变仍会触发重新读取。
- 未运行测试、构建、lint 或真实设备验证。
