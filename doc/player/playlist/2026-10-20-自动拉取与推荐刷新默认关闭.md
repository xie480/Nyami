# 自动拉取收藏夹与首页推荐默认关闭

## 1. 背景与目标

用户要求将“启动时拉取收藏夹最新视频”和“自动刷新首页推荐”两个设置的默认状态改为关闭。只调整未保存设置时的初始行为，保留已持久化的用户选择和手动操作入口。

## 2. 已确认的实现与调用链

- `src/store/settingsStore.ts` 使用 Zustand `persist` 与 MMKV 同步存储；修改前默认值为 `autoRefreshFavoritesOnLaunch: true` 和 `homeRefreshMode: 'automatic'`。
- `SettingsScreen.tsx` 的启动开关直接读取前者；首页自动刷新开关以 `homeRefreshMode === 'automatic'` 作为开启状态。
- `App.tsx` 在认证恢复后的当前进程内，为每个账号最多排入一次启动最新页检查，并先读取启动开关。
- `syncStore.ts` 恢复持久化索引任务时，会将旧任务的 `refreshLatest` 意图与当前启动开关共同判断；关闭时仍可恢复普通索引续传。
- `useHomeRecommendations.ts` 在页面聚焦、自动定时和网络恢复路径中使用自动模式闸门；显式手动刷新绕过自动模式判断。
- 仓库安装的 `zustand/middleware.js` 默认 `merge` 顺序为当前状态后覆盖持久化状态，因此已有字段保留原值，缺失字段回落到新的初始值。

## 3. 方案与兼容性决策

将启动开关默认值改为 `false`，首页刷新默认模式改为 `manual`。沿用现有持久化存储键、合并规则和调用闸门，不做强制迁移或重置。

新安装、设置数据被清理及旧持久化数据缺少相应字段时，两个开关均默认关闭。已有保存的 `true` / `automatic` 仍保持开启，已保存的 `false` / `manual` 仍保持关闭。首页自动刷新间隔保留原值，用户以后主动开启时继续使用。

## 4. 核心修改

已将 `settingsStore.ts` 的 `homeRefreshMode` 从 `automatic` 改为 `manual`，`autoRefreshFavoritesOnLaunch` 从 `true` 改为 `false`。其余设置、开关组件、持久化流程及触发逻辑保持原有实现。

## 5. 验证与风险

已运行 Node 验证脚本：使用 TypeScript 转译当前 `settingsStore.ts` 和实际 `config`，加载仓库安装的真实 Zustand / `persist` / `createJSONStorage`，仅以内存 Map 替代 MMKV 原生存储。以下 5 个场景均断言通过：

1. 无持久化设置时，启动开关为 `false`，首页模式为 `manual`。
2. 旧设置只有其他字段、缺少这两项时，均使用新的关闭默认值。
3. 已保存的 `true` / `automatic` 保持开启。
4. 已保存的 `false` / `manual` 保持关闭。
5. 从新默认值主动开启两个设置后，重新创建并水合 store，开启选择仍保留。

`git diff --check -- src/store/settingsStore.ts` 通过；Git 只提示未来写回会统一为 CRLF，没有空白错误。TypeScript 单文件转译未报告诊断。未为两行默认值新增镜像测试；整个任务的 Jest、Android 构建及 Metro 集成验证见 [玻璃主题修复记录](../../app/ui/2026-10-20-修复明暗玻璃主题材质.md)。

## 6. 最终结果与可复用经验

两个开关对尚未保存相应设置的用户默认关闭；已有选择保持不变。用户仍可手动同步、手动刷新，或在设置中重新开启自动行为。首页在没有推荐快照且保持手动模式时，需要用户主动刷新以生成推荐，这是所请求默认关闭行为的直接结果。

调整偏好默认值时，应先检查持久化合并规则及后台恢复路径，避免误把默认值变更实现为强制清除已有偏好。此处已有闸门覆盖触发链，因此仅调整初始化值即可完成需求，避免重复条件和迁移复杂度。
