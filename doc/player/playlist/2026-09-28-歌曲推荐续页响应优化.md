# 歌曲推荐续页响应优化

## 1. 背景与目标

歌曲推荐列表下滑加载下一页时，用户需要接近列表末尾后才看到新内容。优化目标是让下一页更早进入加载流程，并缩短画像关键词搜索等待。

## 2. 现状与排查

- `SongRecommendationsScreen` 使用 `FlatList.onEndReached` 触发分页，原阈值为 1.2 个可视窗口。
- 个性化续页会按多个画像关键词搜索，等待服务层聚合后再返回；请求受共享自适应限速器约束。
- 上一项优化已将搜索并发调至 5、共享限速上限调至 2 次/秒，并保留 412/429 自动减速。

## 3. 核心修改

- 将 `onEndReachedThreshold` 从 1.2 提前到 1.8 个可视窗口，使网络续页更早开始，减少用户滑到末尾后等待的时间。
- 复用上一项已经提交的五关键词并发搜索和共享限速调整；不改变推荐排序、去重、七日历史过滤或分页游标。

## 4. 风险与验证

- 更早触发可能增加预取请求；列表页仍使用现有 `loadingMoreRef` 防止同一页重复并发加载。
- 静态检查确认分页仍由 `onEndReached` 触发，单页请求仍以既有 `page + 1` 作为游标。
- 未运行测试、构建、lint 或设备端滚动基准；实际等待时间与预取次数需在目标设备观察。
