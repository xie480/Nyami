# 首页个性化推荐与全站搜索

## 1. 背景与目标

当前登录后的默认页是收藏夹列表；底部导航虽有“首页”，但仍是禁用占位。项目已具备本地 tag 画像、B 站全站视频搜索、他人收藏夹与订阅合集目录、音频播放器及自有收藏写入能力。本次把这些能力接入一个面向登录用户的发现首页，减少重复搜索与跨页面操作。

目标包括：提供个性化合集/收藏夹和歌曲推荐；将 B 站在线搜索与本地全收藏搜索分开；在个性化播放中持续补充队列并可将歌曲收藏到自有收藏夹；增加推荐时长、tag 黑名单和推荐音频缓存偏好。

## 2. 现状与已确认边界

- `src/App.tsx` 启动后将已登录用户路由至 `Folders`；`HomeScreen` 目前承担未登录欢迎和登录入口。
- `BottomNavigationBar` 的“首页”没有路由；“收藏夹”指向 `Folders`。
- `FoldersScreen` 已有全站 B 站搜索模式和本地全局索引搜索，但入口与列表页耦合；收藏目标选择、新建收藏夹和平台状态回读已封装在 `favoriteService`。
- `importedPlaylistService` 已按当前 UID 同步用户收藏的他人收藏夹及已订阅合集，并支持在线分页播放；推荐列表只能从该账号已有来源目录中产生。
- `searchTagRecommendations` 现按画像 Top tag 搜索音乐分区；本次扩展为支持指定页、最大结果数、排除 BVID、时长上限与 tag 黑名单。
- 自动缓存同时发生在音频水合和播放事件回调；现有 `noCacheFolderIds` 不能表达个性化来源。
- B 站目录模型未保证提供简介字段。实现容忍响应里的可选简介；缺失时显示“B 站暂未提供简介 · 收录 N 个视频”，不伪造 B 站简介。

## 3. 需求规格

### 功能需求

- **FR-1 首页：**登录用户启动应用进入发现首页；未登录时仍显示原登录欢迎页。首页包含搜索入口、推荐状态与手动刷新、合集/收藏夹推荐和歌曲推荐。
- **FR-2 合集推荐：**从当前 UID 已同步的他人收藏夹/订阅合集目录中，按现有本地 tag 画像做可解释排序；可查看完整推荐列表及简介、UP 主和视频数；打开后复用现有 `Videos` 分页与播放器。
- **FR-3 B 站搜索：**新搜索页默认搜索 B 站全站视频，支持标题关键词、tag、时长条件、结果排序和分页；可切换到本地全收藏索引搜索。搜索结果继续使用现有平台收藏/新建收藏夹能力。
- **FR-4 个性化播放：**歌曲推荐进入现有 `Player` 界面，显示个性化来源、收藏入口和缓存开关。队列接近耗尽时按画像分页取下一批视频并预加载，排除本地已知收藏和本队列重复 BVID。
- **FR-5 推荐筛选设置：**推荐时长过滤默认开启、上限 5 分钟；用户可调整分钟数或关闭。支持批量粘贴多行/分隔符关键词作为 tag 黑名单，tag 子串命中即过滤。
- **FR-6 定时触发：**首次进入应用首页时自动生成合集与歌曲推荐；每 UID 自上次成功刷新满 5 小时后自动更新。离开再返回会检查冷却时间；停留页面时也会在到期后刷新。首页手动刷新可重新生成；按 UID 持久化成功时间和结果。
- **FR-7 缓存设置：**个性化播放自动缓存默认关闭，可在设置或播放页开启；其他播放来源沿用现有缓存规则。

### 非目标与兼容性

- 不新增未经验证的 B 站“全网收藏夹发现”接口。推荐合集来源先限定为项目已有的“我收藏的他人收藏夹 / 我订阅的合集”目录；这是依据当前数据源作出的实现范围推断。
- 除独立的本地推荐过滤历史表外，不改变现有收藏数据 schema、收藏夹列表、收藏页本地搜索和普通播放行为。
- 不增加第三方依赖；沿用 B 站 Cookie/WBI/限速封装、MMKV、tag 缓存和 Track Player。

## 4. 方案与取舍

保留 `HomeScreen` 作为未登录入口，新增登录态 `Discover` 路由，避免把登录流程与推荐首页混在同一个页面。新增发现首页、搜索结果页和合集推荐列表页；合集详情继续跳转现有 `Videos` 页面。搜索页的本地模式会读取当前 UID 的外部播放列表目录，再从全局索引中查找所有自有收藏夹及目录内已同步的视频。

推荐由 UID 隔离的 MMKV 快照保存。成功时间仅在请求成功后更新；自动刷新使用共享 loading 闸门防止首页和合集页重复请求，失败时保留旧快照且不启动冷却。账号切换期间推荐最多等待 10 秒，直到 App 完成本地索引清理并设置当前 UID，再读取画像。歌曲推荐沿用现有 tag 搜索，在服务层增加页码、排除集合和设置过滤；队列由播放器既有水合缓冲逻辑触发下一页，保持调用链集中。

不为每个来源增加独立的远程详情请求。B 站响应有简介时显示该简介；没有简介时显示明确的空状态。这样避免首页对所有收藏夹产生额外 N+1 请求。

## 5. 影响面与风险

- **风险等级：高。** 此改造跨导航、MMKV 设置/推荐状态、B 站搜索与推荐服务、播放器队列和收藏写入，但不触及数据库迁移。
- 推荐仍依赖非官方网页端接口及当前 Cookie，接口字段和账号权限需真实账号验证；搜索/目录失败不得伪装成空结果。
- 无限预加载会持续产生网络请求；继续复用全局限速、逐页加载、取消信号和 BVID 去重，按剩余队列阈值再取下一页。
- 推荐快照、外部来源目录和播放偏好均按当前 UID 使用；切换账号时不得显示上一 UID 推荐或收藏目标。
- 简介字段可能不存在；UI 以“B 站暂未提供简介”呈现，响应缺失不阻断推荐和播放。
- B 站接口格式不变；推荐过滤表通过 WatermelonDB schema 迁移升级，旧 MMKV 缺少设置时使用默认值（5 分钟、黑名单空、个性化缓存关闭）。

## 6. 实际实现

- 新增发现首页、独立 B 站/本地双模式搜索页和合集推荐页；首页入口、Splash 登录后路由及底部“首页”导航现已指向发现页。
- 新增 UID 隔离的 MMKV 推荐快照和 5 小时自动刷新闸门；按最近一次成功刷新时间触发，页面内提供手动刷新。
- 新增外部合集画像排序、合集简介/来源信息展示，并复用已有 `Videos` 来源详情页。
- 全站搜索支持关键词、tag、时长、排序和分页；本地收藏搜索覆盖自有收藏夹以及当前外部目录中已同步的视频。
- 扩展 tag 推荐服务及播放器队列补页；保留顺序队列语义、BVID 去重、账号校验和旧请求取消。
- 新增收藏夹选择/新建弹层，复用现有收藏写入、目标归属校验与平台状态回读。
- 设置页增加推荐视频时长、批量 tag 黑名单及个性化自动缓存偏好；播放器页增加个性化标识、收藏入口和缓存开关。
- 未改 WatermelonDB schema，未增加依赖。

## 7. 验收标准

- **AC-1（FR-1）：** 已登录冷启动进入发现首页；未登录仍进入登录欢迎；点击底部“首页”返回发现页。
- **AC-2（FR-2）：** 推荐卡片显示来源类型、B 站简介或准确的缺失说明、UP 主、视频数及命中画像标签；点击后按现有来源身份浏览完整分页视频。
- **AC-3（FR-3）：** B 站模式仅在提交/翻页时请求全站搜索；标签/时长过滤后的结果可分页去重；切换收藏夹模式后搜索本地索引且不发 B 站搜索请求。
- **AC-4（FR-4）：** 推荐项启动后打开播放器；加收藏可多选现有自有收藏夹或新建；队列低于缓冲阈值后请求下一页，并过滤本地已知收藏、已排队视频和设置黑名单/时长。
- **AC-5（FR-5）：** 默认推荐时长为 5 分钟；修改值或关闭后推荐过滤随之改变；黑名单支持换行、逗号等批量导入并按 tag 子串过滤。
- **AC-6（FR-6）：** 同 UID 上次成功生成未满 5 小时不自动重复请求；到期后在页面聚焦或停留期间自动刷新；失败不更新冷却时间；手动刷新成功后更新快照和冷却起点。
- **AC-7（FR-7）：** 个性化缓存默认关闭时，自动水合和播放事件不写入音频文件缓存；开启后恢复项目现有自动缓存行为，普通收藏夹播放不受影响。

## 8. 验证范围

本轮未新增或运行自动化测试、lint、构建或真机验证；已进行源码静态审查。B 站当前账号接口权限、简介字段覆盖、分页完整性、Android UI/软键盘布局和原生播放器持续补页仍待真机验证。关闭个性化缓存时会阻止新缓存写入，但如同一音频已有缓存文件，播放器仍可复用该文件。

## 9. 关联页面 UI 适配记录（2026-09-27）

### 背景与目标

补充收藏夹首页、收藏夹搜索结果、收藏夹/推荐合集详情、用户画像和设置页的视觉还原。参考图中的歌曲名、用户、数量和隐私标识属于示例；页面只能展示项目模型中真实存在的数据。

- 画像标签只提供标签名和收藏视频计数；画像强度图用实际计数归一化展示，不引入截图中的固定百分比或虚构分类。

- 自有 B 站收藏夹接口模型不含封面、描述或公开状态，因此详情使用已同步视频封面或图标占位，并只显示本机收藏夹名称与索引数。

## 10. 搜索与推荐体验问题修复（2026-09-27）

### 现象与证据

- 用户提供的 Android 日志明确提示 `Icon` 的 `name="music-note-search"` 不在当前 `MaterialCommunityIcons` 图标清单中；该图标位于搜索页空态。
- 本地搜索原先在每次输入变化时同步遍历收藏索引，并在普通 `ScrollView` 中用 `results.map` 创建全部结果卡片。列表规模较大时会增加键入期间的 JS 渲染工作；未使用性能分析器，因此具体设备耗时尚未量化。
- 推荐歌曲服务已有 `excludeVideoIds` 参数和 BVID 去重，但首页画像上下文只把当前可见来源传给推荐服务，隐藏来源中的已同步收藏视频没有进入排除集。
- 推荐合集全量页原有手动刷新按钮，但没有下拉刷新控件。

### 修改与边界

- 空态图标改为图标库已在项目中使用的 `magnify`。
- 本地收藏搜索预先规范化标题和 UP 主名称，使用 React `useDeferredValue` 延后过滤输入，并将结果容器改为 `FlatList` 虚拟渲染；B 站请求仍只在提交或翻页时发起。
- 合集推荐全量页新增 `RefreshControl`，下拉时调用现有手动刷新流程，重新读取收藏来源并生成推荐快照；原顶部刷新按钮仍可用。
- 推荐服务继续用用户当前可见收藏建立画像，但另从全部已同步收藏索引构造 BVID 排除集。首页首批和播放器后续分页都将该集合与当前队列 ID 合并去重。未同步到本机的 BVID 无法参与本地排除。

### 验证范围

- 源码检查确认无效图标名已移除、搜索结果改用虚拟列表、下拉刷新连接到手动刷新，以及首批/后续推荐都传入全量本地收藏 BVID。
- `git diff --check` 无空白错误。本轮没有运行自动化测试、构建、lint 或真机验证；搜索响应性、Android 下拉手势以及 B 站接口返回仍待设备运行确认。

## 11. 首页滚动卡顿优化（2026-09-27）

### 现象与分析

- 首页通过普通 `ScrollView` 展示 4 个合集预览和 4 首歌曲；推荐生成只在每日首次或手动刷新时运行。当前推荐画像最多取 5 个偏好标签，排序规模受配置的 20 个来源上限约束，因此未发现每次页面渲染都会执行的大型同步推荐计算。
- 首页包含 4 个 `GlassView`，都关闭了阴影，但之前仍会在导航交互完成后各挂载一个原生 `BlurView`。`BlurView` 半径取设置值，默认 28；玻璃主题的全屏背景本身已经对背景图应用模糊。重复的局部原生模糊是最可能造成首屏合成和滚动负担的实现热点。
- 以上是基于实现结构的性能判断；设备上应用未运行，当前没有修改前后的帧耗时数据，因此不能把该判断写成已由帧分析器确认的根因。

### 修改

- 首页搜索入口、每日推荐状态、合集预览和歌曲推荐四个玻璃卡片均启用 `noBlur`，保留现有半透明底色、描边和主题背景，避免为每张卡片单独创建原生模糊层。
- `GlassView` 在 `noBlur` 模式跳过延迟模糊调度及对应状态更新；其他使用默认模糊的页面仍维持交互完成后加载模糊的行为。

### 验证与限制

- 源码复查确认首页 4 个卡片均跳过局部 `BlurView`，其他默认玻璃容器仍保留原有模糊流程；`git diff --check` 无空白错误。
- 已检测到 Android 设备，但 `com.bilimusic` 当时没有运行进程，无法读取有效帧统计；本轮未运行测试、构建或安装，因此实际帧率改善尚未量化。
- 首页全屏背景继续使用现有模糊壁纸。建议在设备上对比进入首页后的首屏稳定时间和快速上下滚动；若仍卡顿，应再用 Android GPU/帧分析数据确认图片解码或全局背景模糊是否为剩余热点。

## 12. 五小时刷新与收藏去重（2026-09-28）

### 需求与实现

- 首页和合集推荐共用按 B 站 UID 隔离的刷新快照。原先按当地日期触发，改为按成功时间起算的 5 小时冷却；手动刷新与自动刷新成功后都会重置冷却起点。失败请求保留上一份快照，不改变上次成功时间。
- 聚焦推荐页时检查是否到期；推荐页保持前台时以剩余冷却时间安排一次定时刷新。首页与合集页共用 store 的刷新占用标记，避免两个页面同时请求。应用挂起期间的定时器精度受操作系统调度影响，恢复后会在重新聚焦时补检查。
- 推荐服务同时以 BVID 和规范化标题排除本机已同步的全部收藏（包含隐藏收藏夹及可见外部收藏来源）；规范化包括 Unicode NFKC、去空白和忽略大小写。该逻辑用于首页首批歌曲及播放器按画像补充歌曲。
- 收藏表按“视频 + 收藏夹”保留记录，不能将其现有 `video_id` 改成全局唯一而不改变重复收藏到多个收藏夹的行为。因此收藏重复过滤在读取全量本地索引后进行；第 5 项的推荐历史过滤表另建 ID 与视频标题唯一索引，并按 UID 记录 7 日过期时间。

### 验证与限制

- 源码检查确认旧每日闸门调用已移除，自动冷却从成功时间计算；ID 和标题过滤已传递至首批推荐及后续分页；`git diff --check` 通过。
- 本轮没有运行自动化测试、lint、构建或设备验证。5 小时定时与系统挂起恢复行为仍待真机确认；B 站未同步到本机的收藏无法参与本地去重。

## 13. 七日推荐历史去重（2026-09-28）

### 方案与实现

- 新增 `recommendation_filter` 本地表，仅保存 UID、推荐类型、BVID/合集 sourceKey、规范化视频标题和过期时间，不改变 `video_meta` 的收藏关系记录。
- 水平升级到 schema version 5；新装 schema 和旧库迁移都建立唯一索引：`(uid,item_type,item_id)` 与 `(uid,item_type,title_key)`。合集不填标题键，仅按 sourceKey 去重。
- 首页生成时，在数据库写事务内清理已过期条目、过滤近期歌曲与合集、再写入本轮通过过滤的新推荐，避免并发刷新产生重复。播放器个性化分页的新歌也经过相同服务。
- TTL 固定为 7 天，过期记录按绝对时间判定；筛选时物理删除过期行，释放唯一索引。不同 B 站 UID 的历史互相隔离。

### 验证与限制

- 源码检查覆盖 schema、5 号迁移、DB model/collection、唯一索引 SQL、事务内过期清理与推荐/队列调用点；尚未对既有数据库执行运行时迁移。
- 本轮没有运行测试、lint、构建或设备验证。WatermelonDB Android 原生驱动升级效果及大规模历史清理耗时仍待设备验证。
