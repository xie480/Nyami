# 声音实验室预设特征强化

## 1. 背景与目标

用户反馈现有预设参数变化不够明显，未突出文字描述的特质。本次保持 17 个预设的 ID、名称和用户已保存的自定义参数，强化 16 个非原音预设的频谱对比，并修复会导致预设失效或频段失真的既有问题。

## 2. 已确认的链路与问题

链路：`PresetSelector → eqStore.applyPreset → AudioDSPModule.applyPreset → DSPAudioProcessor → EqAudioProcessorAdapter → ExoPlayer PCM`。预设均为 10 段 Graphic EQ，没有立体声拓宽、混响、磁带噪声或 bitcrusher 实现。

- 多个人声、空气感、现场预设都集中抬升 2–8 kHz，相互频谱特征接近；气氛类的低通/带限特征偏弱。
- `applyPreset` 没有从 Parametric 模式切回 Graphic，选中曲线不一定参与音频处理。
- MMKV 恢复只恢复 JS store，未将恢复状态传入原生引擎。
- `resetToFlat` 调用原生 `reset`，原生仅清历史状态，没有将 Graphic/PEQ 系数恢复原音。
- `BiquadFilter` 和 `RBJFilter` 的历史状态原来被所有交错声道共用；在立体声 PCM 中会串音，滤波器实际工作频率也与标签不符。
- Adapter 保存输入采样率，但未传给滤波器；滤波器一直使用 44.1 kHz。
- 复用 PCM 数组时，旧处理器遍历数组全部容量；较短后续音频块的尾部旧样本也参与滤波和峰值限幅。
- 原生目前没有预放大/自动增益补偿；只在处理后按整个块峰值缩放到 0.95，修改保留这一防削波机制。

上述是源代码确认事实。“是否是用户主观听感不足的全部原因”仍待真机对比试听。

## 3. 方案与边界

1. 通过增强主频段、切除掩蔽频段和区分相近预设，强化音色差异；不单纯把全部频段一起抬高。
2. 描述匹配纯 EQ 能力，不声称没有实现的真实空间拓宽、颗粒噪声、采样率降低效果。
3. 预设应用明确切换到 Graphic；冷启动按已保存参数同步；保留用户 EQ 开关和自定义 PEQ/Graphic 参数，不强制重写已保存的音色。
4. 每个声道持有独立滤波历史，按当前输入采样率计算系数，只处理有效 PCM 长度。保持现有 RBJ 系数和线程锁架构。
5. 既有设备正在使用的已保存曲线保持原值；重新点击同名预设应用本次新参数。

## 4. 验证计划

- Jest：预设切换模式、原音重置、持久化恢复、自定义数据保留和预设特征边界。
- JVM PCM 回归：实际滤波器在 44.1/48 kHz 的中心频率响应、声道隔离、短缓冲尾部、reset、限幅与跨音频块状态连续性。
- Android Kotlin 编译由主任务统一执行。
- 当前分工未进行听感试听；合成 PCM 验证频响和数据流正确性，不能替代耳机/扬声器主观调音。

### 5.2 生效路径与格式修复

- `eqStore`：预设切换到 Graphic，保留 PEQ 自定义曲线和 EQ 开关；原音恢复同时切回 Graphic。持久化恢复后将实际保存的 Graphic/PEQ、工作模式与开关同步原生。
- PEQ 同步按数组顺序映射连续原生槽位，禁用/删除的槽位显式归零，避免不连续业务 ID 或失效滤波器留下音效。
- `DSPAudioProcessor`：每声道独立 IIR 实例；输入格式变化时在同一写锁内更新采样率、声道数和系数，保留用户参数。调节 Graphic 和单个 PEQ 只重算其对应系数。
- `EqAudioProcessorAdapter`：`configure` 仅记录下一段格式，`flush` 才统一激活采样率/声道数/编码并配置 DSP。遵守 ExoPlayer 在 `configure` 与 `flush` 之间仍可提交上一段 PCM 尾块的边界，避免提前按新格式解码旧数据。PCM16 与 Float 路径均传递当前有效样本数。
- `FFTAnalyzer`：接收有效样本数，避免复用数组容量的旧尾部样本进入频谱；按实际声道数跳采样。
- `reset`：Graphic/PEQ 参数和系数一起归零，再清空历史和频谱状态。

### 5.3 实际验证结果

1. `.\node_modules\.bin\jest.cmd tests/unit/eqStore.test.ts --runInBand`：7 项通过。覆盖 PEQ 模式应用预设、原音重置、自定义参数恢复、已选旧曲线保留、禁用/删除槽位归零、手动曲线标记与预设 ID/参数范围。
2. `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-audio-dsp.ps1`：14 项真实 Kotlin PCM 回归通过。脚本从产品 `eqStore.ts` 提取全部 17 个预设，不复制测试专用参数。编译并执行真实 `EqAudioProcessorAdapter`，只为 JVM 环境提供最小 `Log`、编码常量、`AudioProcessor` 接口边界 stub；真实 Android/ExoPlayer API 兼容性仍由 Gradle 编译覆盖。
3. 44.1 kHz 和 48 kHz 下，Graphic 16 kHz 中心增益和 PEQ 8 kHz 中心增益均满足 +6 dB ±0.03 dB 的测试容差；双模式左右声道隔离、双模式原音 reset、格式切换参数保留、短块尾部、Float 缓冲复用连续性、0.95 峰值限制与关闭直通均通过。
4. ESLint 定向执行关闭已有 `prettier/prettier` 格式规则后 0 error；仅有既有 `if (!preset) return` 的 curly warning。新增测试文件已执行 Prettier。
5. `tsc --noEmit --pretty false` 仍失败于已有 `favoriteService.folderId`、旧测试缺少 Jest globals 类型、`trackPlayer_backup.ts` 导入等基线诊断；本次 `eqStore.ts` 与新增测试未出现诊断。
6. 主任务在最终 Adapter 修改后执行 Android 离线 `:app:assembleDebug` 成功（51 秒，433 tasks，38 executed）；生产 Metro bundle 成功。全量 Jest 90 项已执行用例通过，另有 3 套因原有 `NativeEventEmitter` / `RNShare` mock 初始化失败。未安装本次构建或进行设备试听；详细集成与设备边界见 [玻璃主题修复记录](../../app/ui/2026-10-20-修复明暗玻璃主题材质.md)。
7. 格式生效边界回归：先配置 44.1 kHz/单声道/PCM16 并 `flush`，再 `configure` 48 kHz/立体声/Float；`flush` 前继续提交旧 PCM16 尾块，逐样本与旧格式 DSP 参考比较；`flush` 后提交新 Float 数据，逐样本与新格式 DSP 参考比较，均通过。

### 5.4 验证中的环境问题

首次独立 Kotlin 编译使用 PATH 中的 Java 25，Kotlin 1.9.22 无法解析该 JDK 版本。脚本改为读取项目 `android/gradle.properties` 的 JDK（当前 Corretto 21）后通过，不修改全局 Java 环境。脚本可用 `-JavaHome` 与 `-GradleCache` 指定其他本地环境，不下载新依赖。编译保留既有 FFT 局部变量 shadow warning，未阻断测试。

## 6. 风险、价值与后续

- 已保存曲线不会在升级时被强制替换；需重新点击预设应用新版参数。这避免覆盖用户已经习惯或手动调整的音色。
- 强化曲线在不同音乐/耳机上可能有不同主观效果；保留既有峰值限幅，但未加入响度匹配和自动预放大补偿，不同预设响度可能不同。
- `现场`、`大厅`、`Lo-fi`、`8-Bit` 是 EQ 音色风格，不等于真正立体声拓宽、混响、磁带颗粒或 bitcrusher。描述已消除未实现能力的暗示。
- 已确认频响、声道隔离与状态恢复路径；未进行真人试听。后续应使用同一首歌、同一输出设备、接近响度做 A/B，重点检查低频遮蔽、女声齿音、高频疲劳和强限幅段落。
- 可复用价值：形成读取产品实际参数的离线 PCM 验证入口，后续调音可验证真实 DSP 而非只检查数组数值；修复模式/恢复/reset 和多声道格式问题，降低“界面显示已生效但声音未变化”的风险。
