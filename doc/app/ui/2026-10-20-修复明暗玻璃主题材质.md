# 修复明暗玻璃主题材质

## 1. 背景与目标

用户反馈磨砂玻璃明亮、暗黑主题都失去了玻璃感。项目为 React Native 0.74.5 / React 18.2 原生 Android、iOS 应用，自建主题，使用 `@react-native-community/blur` 4.4.1。保留原有布局、导航、交互及普通明暗主题，恢复壁纸穿透、层次和固定播放导航的模糊材质。

采用 ui-ux-pro-max 的成对明暗材质、文字对比及性能原则；使用 web-design-guidelines 中适合原生的可访问性、装饰层、触控与减少动画检查，不将 HTML 规则套到原生。

## 2. 调用链及已确认根因

`settingsStore.themeMode / glassBlurAmount → ThemeProvider → GlassBackground + 页面半透明 surface + GlassView → native BlurView`。

- `GlassBackground` 在导航前绘制，导航和页面容器背景透明，未发现通用层级遮挡。
- 上次界面调整将浅色卡片 alpha 提高至 0.94、深色提高至 0.88；已模糊壁纸几乎被纯色盖住。
- 安装的 Android BlurView 默认 light overlay alpha 0.2、dark alpha 0.64。与卡片底色叠加后，壁纸在两种卡片内理论贡献仅约 4.8% / 4.3%（不含背景蒙层）；原生模糊即使运行也难以看见。
- 底部播放导航同时设置 `noBlur`、`minimal`，不会挂载 BlurView。
- 设置允许模糊值 0；旧 Android RenderScript 要求正半径，因此恢复模糊后必须排除零值原生路径。

上述为源码确认；截图可观察浅色卡片和底栏近似纯白。根因不是对 Android 已执行模糊算法的设备级追踪结论。

## 3. 修复方案与取舍

- 两款玻璃卡片底色 alpha 调整到 0.68，次级表面到 0.82，并加强暗色玻璃边缘。保留不透明 `surfaceRaised` 供弹层及减少透明度回退使用。
- Android BlurView 显式使用主题底色作为唯一的 `overlayColor`，原 content sibling 在 native blur 就绪时背景透明，避免库默认蒙层、主题蒙层叠加，也避免 theme tint 被根视图截图再次捕获。未就绪、零值和轻量表面仍由 content 绘制底色。iOS 保持现有 sibling tint、系统明暗材质及减少透明度回退。
- 底部固定播放导航恢复一个原生 BlurView；列表 `minimal/noBlur` 保持轻量，使用已模糊的共用壁纸，不为每行追加 native blur。
- `requestedBlur <= 0` 不挂载原生模糊，保留主题 tint；重新调高后恢复。
- 半透明度改变后同步调整玻璃主题的强调色、副文字和提示文字；背景可读蒙层抽为 `backdropScrim` token，渲染和对比测试使用同一来源。

不新增依赖，不改普通明暗主题及用户背景图片，不修改用户保存的玻璃模糊度。

## 5. 风险与边界

- 原生 BlurView 会捕获 Activity content root，安装版算法只跳过 BlurView 子树。本次把 Android tint 移至 native overlay 消除了底色自捕获；交互文字仍是 sibling，是否出现可见晕影需在设备中观察，不能仅靠 Jest 确认。没有把内容跨平台移入 BlurView，因为 Android wrapper 固定 `pointerEvents="none"`，iOS Paper/Fabric 内部子视图顺序也不同。
- 恢复固定底栏 blur 增加原生合成工作，未采集帧时间，不能声称性能改善。
- 本次没有 Web 运行目标，因此浏览器 desktop/mobile 检查不适用；以 React Native 测试和 Android 设备证据为准。iOS 材质和旧 Android RenderScript 尚待真机验证。

## 6. 可复用经验

磨砂效果需要同时核查壁纸、原生模糊、系统 overlay 和前景 tint 的合成。为提升可读性调高 alpha 后，必须复查材质是否被覆盖；同时不要通过每行原生模糊恢复外观而扩大长列表渲染成本。
